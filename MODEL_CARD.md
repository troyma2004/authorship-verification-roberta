# Model card: RoBERTa authorship-verification ensemble

## Purpose and contribution

This coursework system predicts whether two English text passages were written by the same author. Xiao Ma implemented the complete Category C solution for the University of Manchester's COMP34812 Natural Language Understanding coursework in 2026, within Group 35: Kanav Gupta, Xiao Ma, and Yangsong Zhou.

The repository preserves the implementation and experiment records. All four trained checkpoints have been recovered locally and packaged for a separate release; the upload is pending. Metadata and tokenizer files are maintained in the repository. This is an academic project; it has not been validated for production use.

## Architecture

Each component uses `roberta-base` through `AutoModelForSequenceClassification` with two output classes: `0` for different authors and `1` for the same author. A pair is encoded jointly as `<s> text_1 </s></s> text_2 </s>`. Inference averages the same-author probabilities from the forward and reversed pair orders.

| Component | Initialisation | Main configuration |
| --- | --- | --- |
| Anchor | Pretrained RoBERTa-base | Maximum 20 epochs with early stopping; 256-token window; pair-swap augmentation; accuracy-based selection |
| Hard-negative continuation | Anchor checkpoint | 3 configured epochs; focal loss, γ = 1.5; feature-based negative-example weighting |
| Symmetry continuation | Anchor checkpoint | 3 configured epochs; squared probability-consistency penalty, λ = 0.1 |
| Long-text specialist | Hard-negative checkpoint | 3 configured epochs; 384-token window; long/extra-long training pairs; focal loss and negative-example weighting |

For negative examples, token Jaccard similarity of at least 0.35 assigns a 2.5× sample weight. URL/email/number-pair indicators or a placeholder match assign a 2× weight. The implementation takes the maximum applicable weight; it does not multiply the two weights. These feature rules do not require the two texts to contain identical URLs or email addresses.

Training preserves raw text: lowercasing and URL, email, and number normalisation are disabled. Input tokenisation uses RoBERTa's tokenizer. Whitespace word counts define the ensemble buckets:

- Total words: short (≤120), medium (121–200), long (201–300), extra-long (>300).
- Absolute difference between text lengths: balanced (≤20), different (21–60), very different (>60).

Each of the 12 buckets has separate weights over the three base models and a classification threshold. Long and extra-long buckets additionally blend the specialist probability with the base ensemble using a bucket-specific coefficient. The inference notebook preserves the selected constants. The code used to search those constants is unavailable.

## Data and training provenance

The recovered course-provided dataset contains **27,643 labelled training pairs**, **5,993 labelled development pairs**, and **5,985 unlabelled test pairs**. Training and development counts agree with the saved training output. Raw dataset texts are not redistributed in this repository. Pair-swap augmentation uses both orders of each training pair; these are not additional independently collected examples. No additional task dataset is documented; the backbone starts from pretrained RoBERTa weights.

The training implementation uses AdamW, learning-rate warmup and decay, gradient accumulation, clipping, and optional GPU mixed precision. The saved log covers only part of the anchor run. Configuration values describe the intended training procedure; they are not a complete record of every completed run. Ensemble-search and automatic bundle-export code have not been recovered, so the repository does not provide an automated reproduction of the full training-to-ensemble workflow.

## Checkpoint recovery

The four recovered safetensors files each contain 201 tensors with 124,647,170 parameters. File hashes and tensor headers were checked, and their model configurations, tokenizer files, and inference metadata match the retained archive artifacts. The [checkpoint manifest](models/model_manifest.json) records file-level provenance. These static checks establish consistency of the recovered files; they do not replace model loading or a new evaluation run.

Saved checkpoint configurations record Transformers 5.3.0. This is the basis for the prepared inference setup, not evidence of a fully tested dependency environment. No new training or neural inference was performed for this release.

## Evaluation

The saved demo output reports the following counts over 5,993 development examples:

| Count | Value |
| --- | ---: |
| True positives: same author | 2,797 |
| True negatives: different authors | 2,176 |
| False positives | 761 |
| False negatives | 259 |

The corresponding accuracy is **0.829801** and macro F1 is **0.827954**, reported as **82.98%** and **0.8280**. These values are derived from the saved counts; they were not regenerated by a new model run for this release.

The development set also informed checkpoint selection, classification thresholds, ensemble weights, and specialist-blending coefficients. These results therefore describe performance after tuning on that set and are not an unbiased estimate of generalisation. No independently evaluated test score is available. The archived demo and coursework CSVs contain 20 and 5,985 unlabelled binary predictions respectively. The coursework prediction count matches the recovered test input, but this alone does not verify input-to-prediction correspondence. Neither prediction CSV represents the reported development evaluation.

ROC AUC, equal error rate, log loss, and Brier score are not reported because the surviving Solution C outputs do not verify them.

## Limitations and use

- Frozen ensemble constants are specific to the recovered checkpoints and should be retuned if models are trained again.
- Development-set tuning can overfit, particularly with separate parameters for 12 buckets.
- Sequence truncation discards content beyond the 256/384-token pair windows.
- Topic overlap may be confused with shared authorship; performance on other domains or languages has not been established.
- The saved artifacts do not support claims about production reliability, calibrated probabilities, or training/inference timing on a particular GPU.
