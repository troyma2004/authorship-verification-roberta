# Authorship Verification with a RoBERTa Ensemble

Predicting whether two English texts were written by the same author using four fine-tuned RoBERTa cross-encoders, pair-order consistency, and an ensemble conditioned on text length.

I implemented **Solution C in its entirety** for the University of Manchester's COMP34812 Natural Language Understanding coursework in 2026. This was part of Group 35's submission, with group members Kanav Gupta, Xiao Ma, and Yangsong Zhou. This repository presents my Solution C implementation.

The repository preserves the training and inference implementations, recorded development results, and the four recovered trained checkpoints. A checkpoint bundle has been prepared for a separate GitHub release; **its upload is pending, so the weights are not yet downloadable from this repository**.

## Approach

- **Anchor model:** RoBERTa-base cross-encoder, with both text orders used during training and their probabilities averaged at inference.
- **Hard-negative continuation:** focal loss and extra weight for different-author pairs with high lexical overlap or URL/email/number-related features. The lexical-overlap rule uses a 2.5× weight; the special-feature rule uses 2×, taking the larger weight when both apply.
- **Symmetry continuation:** a consistency penalty between predictions for the two text orders.
- **Long-text specialist:** a continuation of the hard-negative model, trained on long pairs with a 384-token window instead of 256.

The first three models are combined using separate weights and classification thresholds for 12 buckets, defined by total word count and the difference between the two text lengths. The long-text model is blended into long and extra-long buckets. These ensemble settings were tuned on the development set. Raw text is preserved without lowercasing or URL/email/number normalisation.

## Recovered checkpoints

All four original checkpoints were recovered in September 2026. Their file hashes, tensor headers, configurations, tokenizers, and inference metadata were checked without running the models. See the [checkpoint manifest](models/model_manifest.json) and [recovery notes](ARCHIVE_NOTES.md). The reported result has not been regenerated by a new training or inference run.

Once the checkpoint bundle is published, the intended Google Colab setup is:

1. Download `models.zip`, `model_manifest.json`, and `SHA256SUMS.txt` from the checkpoint release (upload pending). With all three files in one directory, verify them using `shasum -a 256 -c SHA256SUMS.txt` (macOS) or `sha256sum -c SHA256SUMS.txt` (Linux), then upload the ZIP to `/content/models.zip`.
2. Open [`demo_Group_35_C.ipynb`](demo_Group_35_C.ipynb) in Colab. A CUDA GPU runtime is recommended.
3. Run the notebook's install cell. The setup uses Transformers **5.3.0**, the version recorded in the saved checkpoint configurations.
4. Place a CSV you are permitted to use in `/content/data/`, following the [input schema](data/README.md).
5. Set `INPUT_CSV_NAME` to that file's name, then run the remaining cells in order. The notebook extracts the bundles and writes binary predictions.

These instructions describe the intended inference workflow; a fresh Colab environment and the full run have not been verified for this release. The original training, development, and unlabelled test inputs were also recovered locally, but their raw texts are not redistributed here. The ensemble-search code is still unavailable. Frozen ensemble settings belong to the recovered checkpoints and need retuning for newly trained models.
